# PLC 事件身份与条件确认协议 v1

本协议是可选能力。工站的事件号、确认请求和确认回执地址全部留空时继续使用现有触发/响应方式；仅在 PLC 程序完成以下约定并通过现场验收后填写三个地址。普通寄存器读写不能在应用端模拟设备侧的原子条件确认。

## 寄存器与 PLC 责任

| 块 | 长度 | 所有者 | 约定 |
|---|---:|---|---|
| 事件号 | 4 字 | PLC | UInt64，低字在前，零代表未就绪；每次新件/新事件分配新号 |
| 确认请求 | 5 字 | DataTrace | 前 4 字是期望事件号，第 5 字是 Int16 判定结果码 |
| 持久回执 | 5 字 | PLC | 前 4 字是实际接受事件号，第 5 字是实际接受结果码 |
| 原触发地址 | 1 字 | PLC | 继续用于发现需要采集的事件；启用此协议后 DataTrace 不直接向它写结果 |

PLC 必须做到：

1. 事件号在断电、PLC 重启、托盘复用及程序升级后不复用。PLC 不能只用托盘号、循环计数的低 16 位或非保持计数器充当稳定事件号。
2. 置触发之前发布完整事件号与本件数据；在接受本件确认之前保持事件号和采集数据稳定。多字事件号必须提供一致的读取视图，不能读到进位过程中的混合字。
3. 对 5 字请求形成一致快照，并在 PLC 侧原子核对请求身份等于当前事件后才执行结果处理。不能先按结果清触发再检查身份；不能消费网络传输中途的半个请求。
4. 同一身份与同一结果重复请求只执行一次设备业务动作。相同身份的不同结果必须拒绝，不能覆盖已完成的判定。
5. 先发布完整、可保持的回执，再推进物料到下一事件；回执跨 PLC 重启保持。保证应用可能的故障恢复窗口内，原回执仍可核验。
6. 请求块、事件号块、回执块、触发及测量/心跳缓冲区不能重叠。页面与仓储会校验协议块之间及触发的重叠，测量与 PLC 程序内部区域仍须由设备工程师核对。

字地址偏移单位遵循驱动契约：三菱/Modbus/欧姆龙使用字偏移，西门子使用字节偏移。该协议的 UInt64 字序固定低字在前，不跟随点位浮点数的字序设置。

## DataTrace 的行为

采集开始读取身份，判定完成、持久化前再次读取并核对身份。记录与待确认留证同事务保存，冻结连接指纹、触发及三个协议地址、事件号和判定码；spool 同样保留这些事实。

确认时先读取持久回执：身份与结果完全匹配即确认完成，不向可能已经换件的设备写请求。没有对应回执时，只在当前身份仍是原身份的情况下写独立请求块，再核对完整回执。PLC 尚未产生回执或通信失败时保留留证，后续退避核对；不会重新采集或分配流水。启动后的有效触发若没有任何原事件留证，仍按现有策略阻塞并要求现场核验。

设备地址或连接发生变化、旧留证没有身份、双持久化失败或已经要求人工核对时，不自动解除。人工“设备已处理”操作对协议事件也要求原身份与原结果的回执，不能只根据触发寄存器已经改变销账。

## 现场验收

逐项记录设备型号、PLC 程序版本、协议地址、保持区配置和每次试件身份：

- 正常件、NG 件及采集错误结果：回执身份和结果与持久记录一致。
- 写请求已生效但网络应答丢失：重启应用后只核对持久回执，无重复设备动作。
- 身份读取之后、请求写入之前换件：PLC 拒绝旧身份，保持新事件状态。
- 数据采集过程中事件改变：拒绝保存混合事件数据，保持现场核对入口。
- PLC 重启/断电：事件号不复用，已接受回执仍能核对。
- 仅数据库故障、spool 成功：补传后回执结果与原判定一致；双存储故障不写确认。
- 修改连接或任一协议地址后重启：原留证保留，不将旧请求发送到新目标。

软件模拟回归验证的是应用行为；真实 PLC 的保持区、原子处理和断电能力必须在现场验证。本仓库不会根据填了三个地址就声称设备已支持协议。
