复查中新发现的演示数据缺陷也已修正：新建六站演示线首站曲线 Y 缓冲区由 `D2000` 改为 `D2200`，避免与末站触发 `D2000` 重叠；新增回归检查所有演示触发寄存器均不落入曲线缓冲区。不会自动替换既有客户地址映射；旧演示数据与新增工站的默认地址仍应按实际设备检查是否重叠。

配置变更需要重建 PLC 队列时，若旧任务仍在途，就先等待切换完成；不会把新配置快照配到旧连接队列。人工留证诊断使用实际 `CollectRecordId`，避免将 pending 表行 ID 误作业务记录链接。

## 故障闭环操作

1. 在诊断页确认工站、流水、故障原因及启动核对状态；通过关联日志和记录判断数据是否已入库/缓存。
2. 未确认或双存储故障时，保持工站阻塞；先恢复数据库/磁盘/通信。双存储故障只重试原请求保存，不重新读取设备或分配流水。启动时已有效且没有留证的触发不能自动采集，应先核对现场物料与设备，再让设备进入非触发状态，程序实际观察到后才接受下一次触发。
3. Admin/Engineer 在诊断页选择待核对事件，填写原因、物理设备证据并确认危险动作。原设备目标缺失或配置改变时保持阻塞。
4. “同一原事件”模式要求人员先确认设备仍停在原事件，程序再读触发值、单次写原结果并读回；“设备已处理”模式要求当前触发值已离开原触发值，不写旧结果。
5. 检查原数据、触发状态和后续新件，确认只产生预期记录；人工处理事实保留操作者、时间、模式、原因与设备证据。
6. 若需配置回滚，先停用采集、处理现场在途状态，然后从修订历史执行完整回滚；回滚生成新的审计修订。

## 验收限制

- 现有 PLC 协议没有稳定事件号。单次读/写不是设备侧原子条件确认；人员核对需要设备处于受控停止状态。要实现自动安全恢复，应由 PLC 提供事件号及条件确认协议，再独立验证。
- 旧留证缺少原设备目标时保持阻塞，不能通过猜测当前地址自动放行；旧 schema 1 快照仅走明确的兼容路径，不能声称它拥有完整历史冻结能力。
- DB 与 spool 同时不可写时原请求保存在进程内，每工站一份，设备触发不确认。掉电会丢失这份内存请求；不能宣称双介质失效下仍有持久数据保证。存储恢复前应停止生产；重启时的有效触发门禁阻止盲目重采，仍需核对物理状态并处理缺失数据。
- `/healthz` 不等于每个月库事务可写证明；不会猜测 Busy 超龄门槛。现场需定义合法最长采集时间、设置告警并测量任务年龄。
- 在线一致备份会阻塞新业务写入；本轮证明互斥边界与文件校验，没有测量最大数据量下的停顿或执行生产恢复。
- 视觉基线若没有匹配环境指纹，`golden=auto` 仅截图。截图成功不代表像素比较通过，应在固定 runner 上建立并执行 compare 门禁。
- 未执行真实 PLC 断线/重启/迟到应答、真实断电、72 小时长稳、性能/容量压测、渗透测试或生产服务发布。上述项目不能由本机模拟回归替代。
