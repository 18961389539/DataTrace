# DataTrace UI 产品成熟度审核

审核日期：2026-10-12。审核对象：当前本机运行的 DataTrace UI 与工作区实现。源码 HEAD：`9a393c4`。

## 结论

当前 UI 已经有可用的工业应用基础，功能覆盖较完整，但整体仍偏向工程配置和数据展示工具。与成熟交付产品的主要差距是：整线概览能力不足、异常信息没有充分分层、部分状态容易被误读、跨页面操作流程不一致，以及移动端仅完成了布局适配，尚未充分优化任务效率。

视觉美化应排在数据可信度、流程可达性和现场操作效率之后。单纯更换配色、圆角、阴影，无法解决目前最主要的问题。

本报告列出 **32 项问题与改进项**，其中包含实际复现的缺陷、源码确认的风险，以及基于当前界面的产品设计建议。P1 表示应在下一次客户交付前优先解决；P2 表示随后一个迭代解决；P3 表示体验完善。没有据此认定采集后端整体不可用，也没有发现足以在本轮直接认定为 P0 的 UI 问题。

## 审核范围与证据边界

- 实际浏览：实时看板、记录查询、产品追溯、记录明细、报警、报表及参数趋势、波形基线、质量异常列表、新建质量异常、PLC 连接、工站配置、产品型号及限值弹窗、系统设置、PLC 仿真、运行诊断、用户、审计日志。
- 视口：桌面 `1440 × 900`；平板 `820 × 1180`；手机 `430 × 932`；另检查了浏览器默认宽度下的布局。
- 运行环境为 Development，当前有 9 个工站、模拟 PLC、持续生成的采集数据，以及超过 100 条待接手报警。数量和尺寸是审核过程中的观测值，可能随实时数据变化。
- 登录、强制改密、权限拒绝、断线恢复等以源码审查为主；未执行真实角色切换、故障注入或现场设备操作。深色模式、大屏模式本轮以实现审查为主，未完整进行视觉验收。
- 质量异常已有单据的详情与复核流程进行了源码审查；当前列表无单据，未创建单据来验证完整闭环。
- 仅进行了导航、筛选、查看、打开并取消弹窗，以及未提交的临时草稿输入；没有保存业务配置、接手报警、触发仿真、提交异常单或更改用户。
- 本轮没有重新运行整套 E2E、像素基线或性能压测。对现有测试的判断来自测试源码，而非本轮测试通过结果。
- 实际运行程序的 DLL 写入时间为 2026-10-12 13:28:44。源码与运行界面交叉验证，但未进行重建、重新部署；没有把未实际验证的源码路径当作已复现结果。

## 已有的成熟基础

1. 导航已经按运行监控、生产数据、系统配置、账户分组，并有角色菜单控制。
2. 有统一主题、浅深色配色、触屏目标尺寸规则和页面帮助组件。
3. 记录查询有地址栏筛选状态、常用方案、排序、分页、导出范围说明；常用方案按账号隔离。
4. 工站配置和系统设置已有未保存改动提醒与离开保护；工站校验支持定位错误字段。
5. 试读结果带配置快照和过期提示，避免把旧配置试读结果误认为当前结果。
6. 明细使用记录当时的判定限值，包含曲线、源文件、结果码和质量异常入口。
7. 报警区分接手与解除，持续时间不会因接手提前结束。
8. 有断线提示、权限拒绝页面、空数据说明、重试入口、危险操作确认和审计记录。
9. 有几何、触屏、视觉基线和若干完整任务的自动化测试。

因此，改进应保留现有能力，并重新组织其呈现和交互。

## 优先处理的缺陷与可信度问题

### UI-01 · P1 · 趋势统计显示变量名，而非统计结果【实际复现＋源码确认】

**证据：**报表 → 参数趋势，摘要显示“均值 `_trendAverage`”“最小 `_trendMin`”“最大 `_trendMax`”和 `_trendRangeText`。`Reports.razor:408` 将字符串参数写为 `Average="_trendAverage"` 等，未作为 Razor 表达式传值；首尾日期字符串参数同样存在该问题。

**影响：**趋势摘要无法使用，暴露实现细节，明显损害产品可信度。

**改进与验收：**正确传递统计值和区间文本；界面不得出现内部字段名，均值、最小值、最大值须与同一批样本一致，图表首尾时间须与样本范围一致。补充有数据状态下的数值断言。

### UI-02 · P1 · 看板 KPI 读取失败后仍保留旧数字，缺少过期提示【源码确认】

**证据：**`Dashboard.razor:642` 的统计刷新异常被直接捕获，保留之前的班次统计；页面没有与这次失败对应的统计过期状态。采集心跳正常并不能证明报表查询成功。

**影响：**用户可能把停更的产量、直通率当作当前结果，跨班时尤其容易误读。

**改进与验收：**每组统计记录最近成功更新时刻，失败时明确显示“统计更新失败，以下为 HH:mm 的结果”并提供重试；初次失败显示不可用，不能显示成有效的 0。模拟统计服务失败但采集心跳正常时，必须能区分两种状态。

### UI-03 · P1 · “需关注”与报警没有形成统一状态模型【实际复现＋源码确认】

**证据：**看板顶部显示大量过程漂移报警，但工站筛选仍显示“需关注 0”。`Dashboard.razor:700`、`:744` 的排序与筛选仅考虑工站故障和最近一次 NG，不包含过程漂移、预警、未配置判定等状态；Busy 分支也优先于上一件 NG。

**影响：**用户点“需关注”可能找不到正在报警的工站，顶层信息互相脱节。

**改进与验收：**明确“运行故障”“质量风险”“待接手事项”的关系；每个报警必须能映射到相关工站，或明确标为全线事项。上一件 NG 在采集中仍保留质量风险标识；已恢复待接手与当前故障应分别计数，避免把它们混为同一故障状态。

### UI-04 · P1 · 最终 OK 缺少判定覆盖范围说明【实际观察；属于表达风险】

**证据：**追溯流水号 `20261012-002061` 显示“工站 9/9”“最终判定 OK”，其履历中 8 个工站显示未判定。当前许多数值点位未配置限值。

**影响：**“工序完整”和“质量检查完整”容易被理解为同一件事。这里不能仅凭 UI 断言后端判定算法错误，但界面没有解释最终结果究竟覆盖哪些检查。

**改进与验收：**追溯摘要分别展示工序完成度、参与判定的检查范围和未判定原因，例如“按已配置检查项合格；8 站仅采集”。标识字段、非质量字段与应判定但缺失的字段要分开说明。未判定较多时，用户无需逐站展开即可理解最终 OK 的边界。

### UI-05 · P1 · 看板缺少真正的整线概览【实际测量＋源码确认】

**证据：**1440px 桌面下，9 个工站全部逐站纵向展开，页面约高 7,616px；最后一个工站从约 6,910px 才出现，单卡约高 485–943px。`Dashboard.razor:260` 使用每站全宽布局，`StationCard.razor` 默认铺开全部参数和曲线。

**影响：**用户无法快速比较整线，首屏主要展示第一台设备。工站和点位增多后，问题会进一步扩大。

**改进与验收：**提供概览与详细监控两种视图；概览显示工站顺序、运行状态、最近判定、关键参数和异常数量，详细参数按选站展开。保留需要“全部参数”的工作模式，但不要让它成为所有角色的唯一首页。在 9 站场景下，一屏或清晰分页应能扫描全部工站摘要；20–30 站仍需有可控布局。

### UI-06 · P1 · 全局报警横幅持续占用过多空间【实际测量＋源码确认】

**证据：**桌面横幅约高 121px，430px 手机上约高 301px，并用 sticky 持续停留。每页重复展示四条详细消息和剩余数量，已恢复待接手也使用相同的大面积红色。

**影响：**正常任务长期被报警内容挤压，容易形成报警疲劳；手机上尤为明显。当前报警不是整页横向溢出问题，而是有效操作空间不足。

**改进与验收：**默认显示一行摘要，例如“当前异常 8 · 已恢复待确认 101”，严重的采集阻断可单独提升；点击展开详情。手机常态摘要建议控制在一至两行，不持续占据约三分之一屏幕。保留声音、状态和访问报警列表的能力。

### UI-07 · P1 · 质量异常列表的“新建”入口无法直接完成新建【实际复现＋源码确认】

**证据：**点击列表“新建异常单”后，只出现“请从采集记录明细进入”提示，必须再去查询、选择记录、进入明细、重新创建。`QualityIncidents.razor:20` 链接没有源证据参数，`QualityIncidentNew.razor:59` 没有在本页选择源记录的流程。

**影响：**入口给出的预期与实际流程不一致，是明显的任务中断。

**改进与验收：**新建页第一步提供源记录选择器，支持流水号、托盘码、工站和时间搜索，选中后直接进入填写；或将入口明确命名为“选择记录并建单”。列表入口和明细入口最终应落到同一可完成流程。

### UI-08 · P1 · 质量异常草稿缺少离开保护【实际复现＋源码确认】

**证据：**在有源证据的新建页填写未提交的临时异常描述，然后点击“数据查询”，直接离开，没有任何草稿提示。`QualityIncidentNew.razor` 无 NavigationLock 或草稿恢复机制；详情处置表单同样缺少此类保护。

**影响：**长描述和处置措施可能在误切页时丢失，与配置页已有的保护不一致。

**改进与验收：**有实际修改后提示“继续编辑 / 放弃 / 保存草稿”，提交成功后解除保护；草稿不得被误当成正式单据。验证菜单导航、浏览器返回和刷新，并为详情页的未提交处置内容提供相同保护。

### UI-09 · P1 · 明细数值与限值缺少单位【实际复现＋源码确认】

**证据：**ST040 明细显示压力 `13.5766`、规格 `5 ~ 20`；工站温度 `53.0106`、规格 `0 ~ 80`。看板可见 kN、℃，但明细表没有显示。`RecordDetail.razor:453` 的 Display 只返回文本或数值。

**影响：**诊断、截图转交和工艺核对时，脱离看板上下文容易误读单位；显示精度也与看板不同。

**改进与验收：**每个测量值和限值保留采集当时的单位；统一显示精度规则，必要时提供原始精度。没有历史单位时明确标注未知，不用当前配置静默推断。压力、温度、位移的明细与导出语义应一致。

### UI-10 · P1 · 手机弹窗的数值调节按钮仍只有 20px【实际测量＋源码确认】

**证据：**430px 手机下，型号限值弹窗 Increment/Decrement 按钮为 `20 × 20px`。已有 44px 触控规则限定在 `.dt-main`、`.mud-appbar`，没有覆盖弹窗挂载区域。

**影响：**主页面虽然完成触屏适配，关键编辑弹窗仍容易误触。

**改进与验收：**将项目的触控尺寸规则扩展到弹窗，或在触屏下隐藏微小步进按钮、使用清晰的数值键盘/较大调节入口；验收覆盖编辑、确认、帮助和步进控件。44px 是本项目现场操作目标；是否违反 WCAG 2.5.8 还需考虑间距及例外，不能仅凭 20px 直接下完整合规结论。

### UI-11 · P1 · 限值矩阵输入框没有明确的字段可访问名【实际检查＋源码确认】

**证据：**弹窗 116 行、580 个输入框，检查首组输入均没有 label 关联、aria-label 或 aria-labelledby，统一 placeholder 为“默认”。`RecipeLimitDialog.razor:86` 起的数值输入未将点位、字段名称关联到输入框。

**影响：**读屏或语音输入无法可靠辨别“哪个点位的哪道限值”；键盘连续录入时也缺少上下文。

**改进与验收：**每个输入的可访问名包含工站、点位和字段，如“ST040 压力 规格上限”；表头与行头正确关联。实际打开弹窗逐项检查，而不是只检查路由首页。这对应 [W3C 的信息关系要求](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html)；可见说明和程序化关联应分别验收。

## 建议实施顺序

### 第一阶段：修复显示与任务中断

处理 UI-01、02、03、04、07、08、09、10、11；同时修正 KPI 关键省略、正常判定空白和权限说明。

这一阶段的交付要求：没有变量名、没有默默过期的 KPI、异常入口可完成建单、长输入不无声丢失、测量值带单位、关键弹窗能被触屏和读屏操作。

### 第二阶段：重做三个高频工作界面的信息层次

优先看板、报警、查询，再优化工站配置和限值编辑器。保留详细模式和现有能力，加入可控的概览、摘要、分组和更多筛选。

建议产品验收目标（不是外部标准）：

- 1440 × 900 下，9 站的整体状态通过概览可在一个主要视区扫描，不逐站滚 7,000px。
- 430 × 932 下，核心查询输入和提交在首屏；常态报警摘要不占据约 300px。
- 820px 平板选择工站后立即看到该站编辑主体，不先经过整个工站列表。
- 100 条报警仍能快速区分当前阻断、质量风险、已恢复待确认，并直接定位相应对象。
- 116 个点位的型号配置可按工站/搜索/修改状态缩小范围；任何编辑时都看得清点位和字段。

### 第三阶段：设计规范与交付验收

统一标题、表格、筛选、按钮、反馈、标签、本地化和密度；完善图表的触屏/键盘使用；将高数据量和用户任务成功率加入回归验收。

建议让操作员、工程师、管理员分别试做“找 NG 产品并解释原因”“处理一个报警”“配置并试读工站”“建立质量异常并提交复核”。记录成功率、耗时、误操作和需要帮助的步骤，再决定视觉微调。

## 需要补充验证的项目

以下没有当作已确认阻断缺陷，应在后续专项验收中处理：

1. **首帧交互准备状态：**审核中个别导航后的立即点击无效，日志记录过 `No interop methods are registered for renderer 1`。重新观察后点击可成功，不能凭此断言人工作业持续不可用。现有 E2E 也显式等待 circuit 就绪。建议测量弱网/高延迟下首屏按钮可点击与实际接管的时间差。
2. **诊断运行时长：**首次进入诊断页曾显示“已运行 1 秒”，但应用已有长时间采集数据；HealthProbe 的静态 Stopwatch 从类型初始化开始计时。建议用进程/服务启动时刻核对其口径。
3. **颜色与缩放：**浅深色全状态对比度、200% 缩放、强光环境、色觉差异；本轮未完成数值化对比度测量。
4. **实际触摸设备：**图表长按/拖动、软键盘遮挡、扫码枪输入、戴手套操作、横竖屏切换；视口缩放不等于真实触摸验收。
5. **断线和会话失效：**断网重连、服务重启、会话超时后输入与当前位置恢复；当前断线文案不能把服务已停的情况一律保证为“后台正常”。
6. **完整权限与异常单闭环：**操作员、访客实际登录下逐项验证；建单、接手、措施、验证、复核、冲突和再次打开。
7. **交付产物：**生产环境登录视觉、客户品牌资源、打印及 PDF 中文排版、CSV 在常见办公软件的表现；不能用 Development 的首页代替客户交付验收。
8. **大规模与持续运行：**30 工站、每站上百点位、长名称、100–1,000 条报警和常亮大屏的性能；本轮仅确认当前 9 站的数据密度，未做压测。
